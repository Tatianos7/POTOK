# POTOK: ручная проверка меню на Android

Дата: 8 ноября 2026. Сборка `com.potok.fitness.menutest`, название «POTOK Меню ТЕСТ».

## Что проверяет эта сборка

Устанавливаемое Android-приложение запускает существующий офлайн-подбор
`authoringWeekSearchV1` через существующие декодеры каталога и результата.
Каталог из исходного master-файла включается только при локальной сборке.
Он не добавляется в GitHub и не публикуется в рабочий каталог рецептов.

Это ручной тест подбора и просмотра рецептов на справочных данных. Он не
подтверждает серверный сценарий Auth → запрос → worker → сохранение → открытие.
Серверный генератор остаётся выключенным. Приложение имеет отдельный package ID,
не содержит AuthProvider, Supabase-клиента или ключей; разрешение INTERNET удалено.
Съеденная еда, дневник, подписка и базы не изменяются.

## Запуск на телефоне

1. Скачать `POTOK_Menu_Test_20261108.apk` и открыть его на Android 7 или новее.
2. Если Android попросит, разрешить установку этому источнику. Установить
   «POTOK Меню ТЕСТ». Основной POTOK устанавливать заново не требуется.
3. Нажать «Открыть комплектный тестовый каталог». Ожидается 132 рецепта.
4. Выбрать сценарий 1400, 1600 или 1800 ккал, дату начала недели и нажать
   «Подобрать тестовую неделю».
5. Переключить все семь дней, открыть «Открыть рецепт» у блюд. Проверить
   ингредиенты на весь рецепт, шаги и явно неизвестный фактический выход.
6. Выбрать 2000 ккал: на текущем каталоге ожидается сообщение, что в проверенных
   списках подходящий день не найден. Это ограничение поиска, а не доказательство
   невозможности составить такое меню вообще.
7. Сменить сценарий: прежнее меню должно сразу исчезнуть. Повторить подбор.
8. Закрыть и снова открыть приложение: выбрать каталог и собрать неделю заново.
   Сохранение плана между запусками в этой сборке не реализовано.

Не использовать справочные КБЖУ для ведения факта питания. Аллергены, ограничения,
применимость нутриентов, фактический выход и практичность порций ещё не проверены.
В меню назначается одна заявленная в источнике порция без масштабирования.
Отсутствующие граммы, клетчатка или порции не достраиваются.

## Воспроизведение сборки

Нужны Node из `.node-version`, JDK 21, Android SDK platform 36 и build-tools
35.0.0/36.0.0. Gradle скачивается штатным wrapper из шаблона зафиксированной
зависимости Capacitor. Установить зависимости через `npm ci`.

```bash
node --import tsx scripts/contracts/recipe-authoring-test-catalog-v1.ts /path/to/MASTER.xlsx > /private/catalog.json
node --import tsx scripts/build-menu-test-android.mjs /private/catalog.json --apk
```

APK: `android-manual-test/app/build/outputs/apk/debug/app-debug.apk`.
Это debug-подпись для внутренних тестов, не релизная подпись магазина.
Генерируемые Android-файлы и каталог исключены из git.

```bash
node scripts/acceptance/menu-test-browser.mjs
```

Команда поднимает локальный сервер в том же процессе и проверяет именно
собранные ресурсы на трёх мобильных ширинах. Браузер Chromium должен быть установлен
для Playwright. Ни одна команда инструкции не обращается к БД.

## Незавершённая серверная интеграция

В исходном коде transport `GenerationRequestFlowV2` по умолчанию отключён,
`exactPlanPreviewV3` не опубликован как endpoint, worker требует явного включения.
Числовая полнота черновика не заменяет source/identity/portion/allergen approval.
Для серверного ручного теста ещё нужны допущенный тестовый набор, связанный
серверный контекст, развёрнутый тестовый worker/API и настоящий Auth-сценарий.
Изменения Staging, публикация данных и включение worker требуют отдельного
конкретного согласования. Production этим PR не изменяется.
