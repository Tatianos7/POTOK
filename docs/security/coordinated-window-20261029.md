## Предлагаемое окно — ещё не согласовано и не начато

После подтверждения внешней копии, при владельце за Mac, без редактирования
приложения, публикаций из других веток и обслуживания провайдера. Продолжительность
не обещается: при drift, timeout или потере ответа остановка и reconciliation.
Перед началом владелец согласует exact SQL/project/COMMIT и отдельную публикацию
exact client source. Разрешение на подготовку не равно этому разрешению.

1. Зафиксировать source SHA, fixed project, SQL hashes, текущую публикацию и
   отсутствие конфликтующего deployment. Внешняя копия и пароль доступны.
2. Независимый readonly baseline admission. Не подменять baseline при различии.
3. Один запуск exact permanent SQL; до COMMIT сохранены прежние row/sequence
   guards. Не повторять при неопределённом результате.
4. На новом соединении postcommit readonly JSON. При неизвестном результате
   также baseline reconciliation. Ни успех after-check сам по себе, ни отсутствие
   NOTICE не заменяют разбор ответа выполнения.
5. До публикации клиента проверить рабочий HTTP: Auth/API доступны; public API
   отвечает, внутренние схемы остаются закрыты; relocation pg_trgm не нарушила
   согласованный search path. Без broad grants и конфигурационных переключений
   ради прохождения проверки. Только заранее ограниченные read-only запросы.
6. Отдельно разрешённая публикация exact клиента штатным Pages workflow, без
   слияния всей цепочки draft PR в master. Проверить выбранный ref/SHA перед
   отправкой workflow: ref должен существовать и указывать на согласованный
   source. Если двинулся — остановиться. Сам workflow_dispatch ещё не отправлен.
7. Проверить deployment success, адрес/полученную версию и загрузку свежего
   клиента после обновления вкладки. Владелец входит своим существующим аккаунтом,
   проверяет профиль, дневник, фото и Мою программу; без генерации/оплаты/массовых
   тестовых записей. Старые открытые вкладки не считаются обновлёнными автоматически.

Если после COMMIT проверка не проходит: клиент не публиковать, запись остановить,
сохранить состояние, отдельно разобрать узкое исправление вперёд/metadata recovery.
Не возвращать уязвимый старый клиент или blanket grants, не затирать новые строки
старым дампом. Нет автоматического обратного deployment/SQL скрипта.
