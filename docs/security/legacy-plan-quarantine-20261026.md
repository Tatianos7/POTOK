# Legacy program mutation quarantine — Draft, 2026-10-26

This candidate deliberately retires the old client table-by-table creation, replanning and adaptation paths, **including legacy Free program creation**. It is a breaking containment choice awaiting release review, not a completed atomic generator. Production and Staging have not been changed. The trusted generator, Graph and Edge execution remain inactive.

## Problem and resulting behavior

`programGenerationService` previously created/changed parent programs, phases, blocks, days, sessions, versions and adaptation records through separate browser requests. A failure could leave a partial plan; checking Premium in the browser did not authorize those individual database mutations. The existing `potok_nutrition` Graph revision/operation/selection/receipt/CAS contracts use a different persistence model. Wrapping legacy IDs in that model without an explicit binding would not establish atomicity.

All three old service entry points now reject before auth, network or database work with `PROGRAM_MUTATION_CHANNEL_NOT_BOUND`. There is no flag, local override or alternate writer to enable them. My Program disables replanning and explains the temporary unavailability. Existing program reads, pause/resume and execution status remain. Skip records an allowlisted `execution_reason` instead of destroying `plan_payload`; start/complete clear the annotation. Skip/feedback no longer initiate adaptation or claim it occurred. Feedback uses the verified entitlement helper rather than profile tier metadata. A planned or completed session never inserts a food/workout diary fact: **PLAN != FACT**.

The review-only SQL depends on #207's exact scoped reader and #208's history containment. It removes effective client creation/content/topology/head/job mutation permissions on seven core legacy tables and INSERT on versions/adaptations. It retains only authenticated column UPDATE on parent status and session status/reason; existing RLS still applies. Restrictive session policies additionally require an owned, unique parent and matching nutrition/training session type. The nullable reason column has no backfill and cannot modify existing payloads.

Manual feedback, new explanation and guard annotations remain owner-scoped and **untrusted**; they cannot authorize generation or prove a paid entitlement. Existing history cannot be overwritten under #208. This candidate is not a universal immutable ledger: table owners/service roles and unreviewed privileged wrappers are outside this client ACL boundary. It does not close every raw payload, old client cache, stale account response or external caller. Account isolation #186 and full application acceptance remain release gates.

## Verification and scope

- `test.mjs`: isolated PG17 fixture built from public phase-7 sources, actual #201 authority, #196 finance, #206 paywall, #207 projection and #208 history; no hosted catalog or user data. Eleven cases reproduce the old gap, verify exact rollback of rows/columns/ACL/policies, committed old-content preservation, effective table and column denial, inherited-grant and service-capability-loss rejection, own execution/pause compatibility, foreign/ambiguous/type mismatch denial, read projection, unchanged diary facts, service compatibility and replay rejection.
- `client.test.mjs`: actual transpiled client services; six tests cover all retired entry points without runtime dependencies/IO, payload-preserving skip/start/complete, error propagation and verified feedback without adaptation.
- Combined disposable Supabase harness installs this candidate **after** the previous history INSERT compatibility tests. Real Auth/PostgREST tests deny old creation/content/head/version/adaptation requests and overwrite-upserts; own status/reason remain, foreign updates affect no rows, invalid reasons fail and program reads remain. Existing Login/Profile/AuthProvider browser checks continue after installation. This is not the complete My Program UI or all account/cache behavior.
- Root TypeScript/build and existing diary, Premium, account-scope and P5 tests remain required. Embedded PG17 validation is supplemental; native PostgreSQL and real API/browser CI results must be checked on the exact published head.

No original eight pinned inputs or private restored runner have been changed. The owner backup's original 112 tables/14888 rows have **not** been tested with this candidate. Old session shape, PG17 nonsuperuser postgres, ownership, RLS, scoped reader source and effective permission preservation are guarded. Inherited leaks or a service capability inherited solely through PUBLIC cause an atomic failure; the candidate never changes role membership or adds broad service privileges. Reapplication intentionally fails before mutation when the new column already exists, rather than silently accepting drift.
