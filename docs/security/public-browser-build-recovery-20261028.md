# Public browser build recovery after slow download

Owner's first attempt stopped after exactly 1,200 seconds. The public archive and runtime/manifest SHA checks passed. The build log shows Debian arm64 packages installed, Chromium's first download endpoint returning HTTP 400/GatewayExceptionResponse, fallback download progressing to 10%, then BuildKit context cancellation. No image ID, self-check or receipt was produced; no database was contacted. Available Mac storage was 13 GiB after the attempt. This is a build-time cancellation, not failed application acceptance.

`private-browser-resume.mjs --resume-public-runtime SOURCE_ROOT BUILD_DIR` validates the original runtime helper SHA, its unchanged 602-input manifest, every copied context file and the exact Dockerfile. The only permitted context files are that manifest's public sources plus Dockerfile: extra files, env files, symlinks, tamper, another parent/root, an existing image ID or a completed receipt stop before Docker. The original source archive, copied context and canceled build log remain intact.

Recovery repeats the same cache-enabled Docker build with a fixed one-hour limit, logs plain progress in a fresh owner-only `resume.*` directory, verifies immutable image ID/architecture/non-root user/source label, then performs the original read-only non-root network-none self-check. Partial work inside a canceled RUN may repeat; the archive is not downloaded again and cached completed layers are retained. No timeout, Dockerfile, dependency, source-manifest or image-content change is made to the original builder or image contract. The recovery helper is outside the image inputs; the expected public source digest remains a10bbd130ce569ec2fcb5ba0c8bba1c0e45524752f233f76a2bedec50deaf37a.

Only a successful self-check marker permits a new receipt.json in the original build folder. The failed image-id location is not overwritten; the new attempt has its own image-id.txt. Failure preserves build/self-check output and creates no success receipt. No automatic retry, cache prune, container/volume reset or image deletion occurs. There is an 8 GiB preflight; this does not guarantee arbitrary later disk usage. The helper uses only a local Unix Docker endpoint and public build inputs; it never inspects service environments or connects Auth/API/database volumes. Account data and the earlier successful post-ACL API proof remain outside this operation.

Five new synthetic adapter tests exercise cache/time limit/command boundaries, immutable source/context validation, no private build-context additions, failure log preservation, image-contract rejection, marker-gated receipt and overwrite/mode refusal. The existing packaged real browser CI still validates the unchanged image. Source/CI success is not a Mac prepared-runtime receipt or full-copy UI acceptance; wait for the owner's actual PRIVATE_BROWSER_RUNTIME_PREPARED_OK.
