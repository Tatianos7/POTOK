## Explicit scope split

**P5-03C (pilot nutrition evidence prerequisite):**
- Food/Nonfood evidence issuance stays unmounted until real authority, raw/canonical source checks, DB grants, staging-only Auth/PostgREST, and immutable receipts have been independently verified.
- A closure fence is **required before any live issuance** that stores account-linked actor/receipt/history. The issuer must acquire a trusted per-account lock *inside the same PostgreSQL transaction as its write*, after verified Auth and before all evidence/catalog locks; it must deny unknown/CLOSING/CLOSED and serialize against closure. An HTTP preflight or injected client observation is **never sufficient**.
- Preserve current exact idempotency and UNKNOWN recovery. If closure races a retry, resolve the original operation with authorized minimal receipt or explicitly return a blocked/unknown state. Do not fabricate rollback, replay after erasure, or generate a new key.
- Do not claim that source-only tests or the disposable closure prototype prove the actual issuer uses this fence. Existing issuer SQL **does not** call the closure prototype.
- A reviewer may merge inactive code after independent review of its nondeployment boundaries, but **activation, SQL apply, real reviewer issuance, or publication remains blocked** until the closure fence and retention policy are implemented and staging accepted. This document is not permission to merge.

**Separate account deletion program (not a prerequisite to writing P5-04 request/status code):**
- Full closure journal, cross-product deletion of diary, private recipes, personal food, premium/FACT, profile/Auth, storage, logs and backups.
- Owner-approved finite retention schedule, legal holds, proof of non-linkability, independent shared catalog preservation, and crash recovery.
- Separate schema migrations and staging end-to-end acceptance; no implicit CASCADE or mutation of immutable proofs.
