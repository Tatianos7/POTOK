## Implemented

- Added `missingFoodDraftService.applyOwnerApprovedDraft(draftId)`.
- The service calls only:
  - `public.apply_owner_approved_missing_food_draft(p_draft_id)`.
- The service maps RPC output into:
  - `result`;
  - `foodId`;
  - `error`.
- Empty/missing RPC response maps to `insert_failed`.

## Admin UI

Updated `/admin/missing-food-review`:

- shows `Owner apply food` only for draft rows with `status = 'ready_for_owner_apply'`;
- hides the button for draft statuses other than `ready_for_owner_apply`;
- disables the action if `applied_food_id` is already filled;
- prompts explicit confirmation before RPC call:
  - creates 1 core food;
  - aliases are not created;
- displays RPC result and `food_id`/error;
- reloads queue/draft data after the RPC returns;
- shows applied food id for already-applied drafts.

The UI does not call Alias Apply and does not write Food Core tables directly.
