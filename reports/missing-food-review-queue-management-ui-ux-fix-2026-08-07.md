## Issue

After Missing Food Review management UI was added:

- the `Missing food` badge in `/admin/search-review` could visually read like an action;
- after owner smoke, a card such as `Сырник` could still show `Review rows ещё нет`;
- the row actually existed in `food_missing_review_queue`, but Search Review displayed only alias review rows from `food_search_review_queue`.

## Fix

`/admin/search-review` now reads both review surfaces:

- Search/Alias review rows from `food_search_review_queue`;
- Missing Food Review rows from `food_missing_review_queue`.

Missing rows are linked back to the Search Review card by:

- `normalized_query`;
- `context`;
- `classification`.

When linked missing rows exist, Search Review shows them in the Review queue area instead of the empty state.

## UI Behavior

Updated behavior:

- `Missing food` remains a label, not a button.
- The label is styled with `cursor-default select-none`.
- `В missing review` remains the explicit action.
- After successful create/update, Search Review reloads items and missing queue rows.
- Linked missing queue rows show:
  - status;
  - suggested name or query;
  - frequency;
  - comment when present.
- Added explicit action:
  - `Открыть missing queue`
- The action opens:
  - `/admin/missing-food-review`

If a missing row already exists, the card now shows it in Review queue instead of `Review rows ещё нет`.
