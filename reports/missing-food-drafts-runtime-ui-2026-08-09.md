## Service Contract

`missingFoodDraftService` writes only to:

- `public.food_missing_food_drafts`

It reads `public.foods` only for duplicate warnings:

- exact `normalized_name`;
- shared sources only: `core`, `brand`;
- no insert/update/delete to `foods`.

It never writes to:

- `public.foods`;
- `public.food_aliases`.

It never calls:

- Alias Apply RPC;
- any food creation RPC.

## Draft Fields

The runtime/UI supports the MVP draft fields:

- `name`
- `normalized_name`
- `category`
- `source = core`
- `unit = g`
- `calories`
- `protein`
- `fat`
- `carbs`
- `fiber`
- `data_source`
- `source_url`
- `source_notes`
- `reviewer_notes`

Fiber remains nullable:

- empty fiber input is saved as `null`;
- `0` means confirmed zero.

Brand and barcode are not active in this MVP.

## UI Behavior

`/admin/missing-food-review` now shows a Food Draft panel only for rows with:

- `status = approved_for_food_draft`

The panel can:

- create a draft by `source_review_id`;
- update an existing draft by `source_review_id`;
- save status `draft`;
- save status `needs_revision`;
- save status `ready_for_owner_apply`;
- save status `rejected`;
- show validation errors;
- show duplicate warnings against existing shared `foods.normalized_name`.

The UI does not show:

- `Create food`;
- Alias Apply controls for draft rows.

## Ready Validation

`ready_for_owner_apply` is blocked unless the draft is complete:

- non-blank name;
- non-blank normalized name;
- non-blank category;
- calories/protein/fat/carbs present and finite/non-negative;
- fiber empty or finite/non-negative;
- non-blank data source.

The UI also blocks `ready_for_owner_apply` while duplicate shared foods are found.
