## Missing Queue Payload

The runtime writes:

- `query`
- `normalized_query`
- `context`
- `frequency`
- `classification = 'missing_canonical_food'`
- `status = 'pending'`
- `source_event_ids`
- `suggested_name`
- `comment`
- `metadata`

Metadata is limited to review context:

- `event_type`
- `last_seen`
- `result_count`

Existing pending rows are updated with:

- latest display `query`;
- max observed `frequency`;
- merged unique `source_event_ids`;
- refreshed `suggested_name`, `comment`, and metadata.

## UI Behavior

`missing_canonical_food`:

- shows the `Missing Food Review` panel;
- shows why Alias Apply is unavailable until a canonical food exists;
- exposes explicit `В missing review` action.

`alias_candidate`:

- does not show Missing Food Review as an Alias Apply replacement;
- keeps the existing Alias Review / Alias Apply path.

`ambiguous_broad_query`:

- shows disambiguation guidance;
- does not show Missing Food Review action.

`typo_or_prefix`:

- shows reject/snooze/noise guidance;
- does not show Missing Food Review action.

Existing approve/reject/snooze and Alias Apply gating were preserved.
