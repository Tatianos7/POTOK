## Safety

- Runtime/UI code changed only for Admin Search Review classification display.
- Production DB schema was not changed.
- Storage buckets and policies were not changed.
- Classification is not persisted to DB.
- RPC was not called.
- No aliases were added.
- No foods were created.
- No writes were made to `foods` or `food_aliases`.
- No import/backfill/recompute was run.
- Existing approve/reject/snooze queue flow was preserved.
- No PR was created.

## Implemented

- Added computed Search Review classifications:
  - `alias_candidate`
  - `missing_canonical_food`
  - `ambiguous_broad_query`
  - `typo_or_prefix`
- Added a classification reason line for each review item.
- Added classification badges in `/admin/search-review`.
- Kept classification runtime-only; no migration and no DB persistence were added.

## UI Behavior

Classification guidance:

- `alias_candidate`: shows "Можно рассматривать Alias Apply".
- `missing_canonical_food`: shows "Нужен missing food review".
- `ambiguous_broad_query`: shows "Нужна дисамбигуация".
- `typo_or_prefix`: shows "Шум/префикс".

Alias Apply controls:

- shown only for approved rows when the parent item is classified as `alias_candidate`;
- hidden for approved `missing_canonical_food`, `ambiguous_broad_query`, and `typo_or_prefix` rows;
- replaced with the classification guidance message for non-alias approved rows.

Existing queue flow:

- pending rows can still be approved/rejected/snoozed/commented;
- candidate row creation/update remains unchanged;
- no direct runtime writes to `foods` or `food_aliases` were added.

## Classification Source

The service computes classification from existing read paths only:

- review event type;
- event candidate ids;
- exact `food_aliases.normalized_alias` lookup;
- exact shared `foods.normalized_name` lookup for `source in ('core', 'brand')`;
- contains candidate count for broad/ambiguous detection.

The current known production examples are represented:

- `стейк` -> `missing_canonical_food`;
- `гов`, `говя`, `говяд` -> `ambiguous_broad_query`;
- typo/prefix/noise terms -> `typo_or_prefix`.
